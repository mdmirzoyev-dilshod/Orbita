## 1. Цели версии 2.0

1. **Сотрудник и руководитель работают с «Орбитой», не выходя из Telegram.** Весь функционал сайта доступен как Mini App внутри бота.
2. **Голос — основной способ ввода.** Расходы, задачи, планы и вопросы задаются голосом на русском и узбекском (латиница и кириллица, смешанная речь).
3. **Контроль времени.** Задачи видны на диаграмме Ганта. Система сама предупреждает о перегрузке и наложениях, напоминает о сроках и каждое утро присылает отчёт.
4. **Единые данные везде.** Любое действие на сайте, в Mini App или кнопкой в чате бота мгновенно отражается в двух других местах.
5. **Личная продуктивность.** День планируется автоматически, приоритеты видны по матрице «важно / срочно», работа идёт фокус-отрезками (Pomodoro).
6. **Деньги без ручного ввода.** Расход записывается по фото чека, обязательные платежи напоминают о себе и записываются в один клик.

**Вне рамок 2.0:** нативные приложения iOS/Android, интеграция с 1С, банковская синхронизация расходов, CRM.

## 3. Что уже есть в версии 1.x

Чтобы не делать заново, фиксируем текущее состояние:

- **Сайт:** обзор руководителя («Командный центр»), задачи (шкала по срокам, доска), «Мои планы» и привычки, «Кошелёк» с дашбордом, команда, уведомления, тарифы, админка оплат, светлая и тёмная тема.
- **Вход:** через Telegram (deep link и одноразовая кнопка входа).
- **Бот:**
  - уведомления о задачах;
  - кнопки «Принял / Сделал / Нужно больше времени»;
  - фото-отчёты и чек-листы;
  - продление срока (+2 ч / +1 / +3 / +7 дней);
  - быстрый ввод расхода текстом («45000 такси»);
  - голосовые → ИИ (OpenAI: распознавание и разбор) → черновик задачи с кнопкой «Поставить», расход, пункт плана, комментарий;
  - команды /tasks, /plan, /wallet.
- **Планировщик (раз в 30 с):** утренняя и вечерняя сводка, напоминания по задачам и планам, «скоро срок», «срок истёк», повторяющиеся задачи, напоминания о конце пробного периода.
- **Тарифы и оплата:** пробный месяц, лимиты ИИ, Payme и Click по QR.
- **Технологии:** Node.js 20, Express, PostgreSQL, ванильный JS на фронтенде, хостинг Railway, Telegram Bot API (long polling).

**Ограничения 1.x, которые закрывает 2.0:**
1. Mini App нет: из бота можно только перейти на сайт.
2. У задачи нет времени начала и длительности, есть только срок (дата и опционально время). Без этого невозможны Гант и проверка наложений.
3. Голосовой черновик задачи можно только поставить или отменить, а также сменить исполнителя. Правки полей и перезаписи голосом нет.
4. Изменения на сайте видны в другом клиенте только после перезагрузки (нет реального времени).
5. Утренняя сводка содержит только задачи, без расходов и итогов вчерашнего дня.
6. Кнопки напоминания ограничены: нет «Напомнить позже» с выбором времени.

## 4. Общая архитектура 2.0 и принцип синхронизации

### 4.1. Схема

```
 ┌────────────┐   ┌──────────────┐   ┌────────────┐
 │  Чат бота   │   │  Mini App     │   │   Сайт      │
 │ (кнопки,    │   │ (Telegram     │   │ (браузер)   │
 │  голос)     │   │  WebView)     │   │             │
 └─────┬──────┘   └──────┬───────┘   └─────┬──────┘
       │ Bot API         │ HTTPS + SSE     │ HTTPS + SSE
       ▼                 ▼                 ▼
 ┌─────────────────────────────────────────────────┐
 │              Сервер «Орбиты» (Node.js)            │
 │  REST API · Обработчик бота · Планировщик · ИИ     │
 │  Шина событий (in-process + PostgreSQL NOTIFY)     │
 └───────────────┬─────────────────────────────────┘
                 ▼
        ┌──────────────────┐        ┌──────────────┐
        │   PostgreSQL       │        │ OpenAI (STT,  │
        │ (единый источник)  │        │  разбор)      │
        └──────────────────┘        └──────────────┘
```

### 4.2. Принципы

1. **Единый источник правды — база данных.** Ни один клиент не хранит собственную копию состояния дольше, чем до следующего события.
2. **Одна функция — одно действие.** Любое изменение (сменить статус, отметить напоминание, записать расход) выполняет одна серверная функция. Её вызывают REST API (сайт, MA), обработчик кнопок бота и обработчик голоса. Дублирования логики нет.
3. **После каждого изменения сервер публикует событие:**
   ```json
   { "type": "task.updated", "companyId": 12, "userIds": [5, 9], "entityId": 341, "version": 17, "at": "2026-11-02T09:15:02+05:00" }
   ```
   Типы событий:
   - `task.created`, `task.updated`, `task.deleted`;
   - `comment.created`;
   - `plan.created`, `plan.updated`, `plan.deleted`;
   - `habit.marked`;
   - `wallet.created`, `wallet.updated`, `wallet.deleted`;
   - `reminder.fired`, `reminder.acted`;
   - `report.ready`;
   - `warning.created`.
4. **Доставка событий:**
   - **Сайт и MA** получают события через **Server-Sent Events** (`GET /api/events`, держит соединение, переподключается автоматически). Получив событие, клиент запрашивает изменённую сущность (`GET /api/tasks/:id` и т.п.) или обновляет срез состояния.
   - **Чат бота:** если событие меняет состояние сообщения с кнопками (например, задачу отметили выполненной на сайте), сервер редактирует это сообщение в Telegram (`editMessageReplyMarkup` / `editMessageText`). Для этого хранится связь «сообщение ↔ сущность» (таблица `tg_msgs`, расширяется).
5. **Масштабирование:** при запуске нескольких экземпляров сервера события передаются между ними через PostgreSQL `LISTEN/NOTIFY` (канал `orbita_events`). При одном экземпляре — внутренняя шина.
6. **Версионирование:** у задач, пунктов плана и записей кошелька появляется поле `version` (растёт при каждом изменении). Клиент передаёт версию при правке. При конфликте (версия устарела) сервер отвечает `409`, клиент показывает актуальные данные и предлагает повторить.
7. **Идемпотентность:**
   - нажатие одной и той же кнопки дважды (в боте или MA) не создаёт дублей;
   - у запросов на создание есть заголовок `Idempotency-Key`;
   - у колбэков бота — проверка текущего состояния.
8. **Время:** все расчёты в часовом поясе компании (по умолчанию Asia/Tashkent). В будущем часовой пояс задаётся в настройках компании.

### 4.3. Критерий синхронизации (общий для всех требований)

> Действие, выполненное в любом из трёх клиентов, отображается в двух других **не позднее чем через 3 секунды** при наличии интернета. Сообщение бота с кнопками меняет вид в течение 5 секунд.

## 5. Требование 1. Telegram Mini App — полный перенос «Орбиты» в бота

### 5.1. Цель
Пользователь открывает «Орбиту» внутри Telegram одной кнопкой и получает весь функционал сайта без отдельного входа и без браузера.

### 5.2. Точки входа
1. **Кнопка меню бота** (Menu Button, слева от поля ввода) — «🪐 Орбита». Настраивается через `setChatMenuButton` с типом `web_app`.
2. **Кнопки в сообщениях бота** (`web_app` inline-кнопки) с переходом сразу в нужный раздел:
   - «Открыть задачу» → `…/app#task=341`;
   - «Открыть отчёт» → `…/app#report=2026-11-01`;
   - «Кошелёк за месяц» → `…/app#wallet`.
3. **Команда `/app`** — сообщение с кнопкой открытия.
4. **Ссылка-приглашение** `t.me/OrbitaUzbot/app?startapp=join_<код>` — новый сотрудник принимает приглашение и сразу попадает в Mini App компании.

### 5.3. Авторизация в Mini App
1. Mini App получает от Telegram строку `initData` (`window.Telegram.WebApp.initData`).
2. При запуске MA отправляет `POST /api/auth/webapp { initData }`.
3. Сервер проверяет подпись по официальному алгоритму:
   - `secret_key = HMAC_SHA256("WebAppData", BOT_TOKEN)`;
   - `hash = HMAC_SHA256(data_check_string, secret_key)`;
   - `auth_date` должен быть не старше 24 часов.
4. По `user.id` находится пользователь (`users.tg_id`) или создаётся новый. Выдаётся сессия (cookie `orb_s` с `SameSite=None; Secure`, так как MA открыт во встроенном WebView) **и** токен в ответе. Токен MA хранит в памяти и передаёт в заголовке `Authorization: Bearer`, потому что некоторые клиенты Telegram не сохраняют cookie.
5. Без валидной подписи — ошибка `401`, данные не выдаются.
6. Параметр `start_param` (`join_<код>`, `task_<id>`) обрабатывается после входа.

### 5.4. Состав Mini App
MA — это тот же фронтенд, что и сайт (один код), с адаптацией под Telegram.

| Раздел | Руководитель | Сотрудник | Особенности в MA |
|---|---|---|---|
| Главная / «Сегодня» | Командный центр (сжатый) | Мои задачи на сегодня | Первым блоком «Сегодня»: задачи и планы с временем |
| Задачи | Список, доска, **Гант** | Мои задачи, **Гант** | Свайп по задаче: «Сделал», «Перенести» |
| Мои планы | ✓ | ✓ | Отметка по тапу, напоминания |
| Кошелёк | ✓ | ✓ | Кнопка записи голосом |
| Команда | ✓ | Просмотр | Приглашение через «Поделиться» Telegram |
| Отчёты | ✓ | ✓ | Утренний отчёт за любой день (Требование 7) |
| Уведомления и настройки | ✓ | ✓ | Время отчёта, напоминаний, тема |
| Тариф и оплата | Владелец | — | Оплата по ссылке Payme/Click |

### 5.5. Интеграция с Telegram WebApp API
- **Тема:** берётся из `themeParams` и `colorScheme` Telegram (светлая/тёмная) и маппится на CSS-переменные «Орбиты». Ручной переключатель «День / Ночь» в MA тоже работает, выбор сохраняется на сервере в настройках пользователя.
- **Кнопки Telegram:**
  - `MainButton` — основное действие экрана («Сохранить», «Поставить задачу»);
  - `BackButton` — возврат на предыдущий экран вместо стрелки в интерфейсе.
- **Тактильный отклик** (`HapticFeedback`): при отметке «Сделал» — `notificationOccurred('success')`, при ошибке — `error`.
- **Размеры:** `expand()` при запуске. Безопасные отступы — `safeAreaInset` и `contentSafeAreaInset`.
- **Закрытие с несохранёнными изменениями:** `enableClosingConfirmation()` на экранах с формами.
- **Голос в MA:** кнопка микрофона записывает аудио через `MediaRecorder` (если клиент Telegram даёт доступ к микрофону). Если нет — показывается подсказка «Запишите голосовое в чат бота» и кнопка «Перейти в чат» (`close()` + сообщение-подсказка в чат).
- **Поделиться:** приглашение сотрудника через `switchInlineQuery` или `shareMessage` (если поддерживается), иначе — копирование ссылки.

### 5.6. Производительность MA
- Первый экран — **не более 2 секунд** на 4G.
- Размер JS и CSS первого экрана — **не более 250 КБ** (gzip).
- Тяжёлые блоки (Гант, графики кошелька) загружаются по требованию.

### 5.7. Критерии приёмки
1. Кнопка меню «🪐 Орбита» открывает MA. Вход происходит автоматически, без ввода данных.
2. Поддельная или устаревшая `initData` отклоняется (тест с изменённым `hash`).
3. Все разделы из таблицы 5.4 работают в MA на Telegram iOS, Android и Desktop.
4. Тема MA совпадает с темой Telegram при первом запуске.
5. Задача, отмеченная выполненной в MA, через ≤ 3 с показана выполненной на сайте. Сообщение о ней в чате меняет кнопки на «✅ Выполнено» в течение 5 с.
6. Ссылка `startapp=join_<код>` добавляет сотрудника в компанию.

## 6. Требование 2. Расходы полностью голосом

### 6.1. Цель
Любая операция с расходами и доходами выполняется голосом: запись, исправление, удаление, вопросы о тратах.

### 6.2. Поддерживаемые голосовые команды

| Пример фразы (рус / узб) | Действие | Результат |
|---|---|---|
| «Бензинга 100 минг сўм харажат қилдим» / «Потратил 100 тысяч на бензин» | Записать расход | 100 000 сум → «Бензин и авто», сегодня |
| «Вчера обед 85 тысяч и такси 30» | Несколько расходов | 2 записи: «Кафе и рестораны» 85 000, «Транспорт и такси» 30 000, вчерашняя дата |
| «Получил зарплату 8 миллионов» | Доход | +8 000 000 → «Зарплата» |
| «Исправь последнюю: не 100, а 120 тысяч» | Изменить последнюю запись | Сумма меняется на 120 000 |
| «Последний расход это не бензин, а продукты» | Сменить категорию | Категория → «Продукты» |
| «Удали последний расход» | Удаление | Удаление с кнопкой «↩️ Вернуть» на 10 минут |
| «Сколько я потратил на этой неделе?» | Вопрос | Сумма за неделю и топ-3 категории |
| «Сколько ушло на бензин в октябре?» | Вопрос по категории | Сумма по категории за период |
| «Поставь лимит на кафе 1,5 миллиона» | Бюджет | Лимит категории на месяц |

### 6.3. Распознавание сумм
Поддерживаются:
- цифры: «100000», «100 000», «100.000»;
- слова: «сто тысяч», «юз минг», «yuz ming»;
- сокращения: «100к», «100 тыс», «1,5 млн», «bir yarim million»;
- валюта: «сум», «сўм», «so‘m», «сумов»; без валюты по умолчанию сумы.
- Доллар и рубль («50 долларов») — запись в сумах по курсу ЦБ на дату операции, с пометкой в заметке «$50 по курсу 12 023». Курс обновляется раз в сутки.

### 6.4. Категории и сопоставление
- Используется текущий справочник категорий (14 расходных и 3 доходные).
- ИИ получает список категорий и словарь синонимов (рус/узб). Примеры: «бензин, заправка, benzin, yoqilg‘i, газ, метан, пропан» → «Бензин и авто»; «садака, хайрия, xayriya» → «Садака и помощь».
- Если уверенность сопоставления ниже 0,7 — бот показывает **3 вероятные категории кнопками** и «Другая…».
- Пользователь может добавить **свою категорию** (до 10 своих категорий): голосом («добавь категорию “Ремонт офиса”») или в MA.
- **Самообучение:** если пользователь исправил категорию для слова (например, «Корзинка» → «Продукты»), это сопоставление запоминается для него и в следующий раз применяется сразу (таблица `wallet_rules`).

### 6.5. Процесс (поток) записи расхода голосом
1. Пользователь отправляет голосовое боту (или в MA).
2. Бот отвечает: «🎙 Распознаю…» (действие `typing`).
3. STT → текст. Бот показывает расшифровку: `🎙 «Бензинга 100 минг сўм харажат қилдим»`.
4. Разбор → 1…N операций.
5. **Сразу сохраняет** (расходы — без лишнего подтверждения, это быстрые записи) и отвечает карточкой:
   ```
   ✅ Расход: 100 000 сум — ⛽ Бензин и авто
   📅 Сегодня · 📝 бензин
   За ноябрь: расходы 2 450 000 сум
   [✏️ Изменить] [🏷 Категория] [↩️ Отменить]
   ```
6. Кнопки:
   - **✏️ Изменить** — меню: «Сумма», «Дата», «Заметка», «🎙 Перезаписать голосом»;
   - **🏷 Категория** — список категорий кнопками (по 2 в ряд);
   - **↩️ Отменить** — удаление записи.
7. Правка суммы: бот просит «Напишите или скажите новую сумму» — ответ текстом или голосом.
8. Любая правка мгновенно видна в «Кошельке» на сайте и в MA (событие `wallet.updated`).

### 6.6. Ошибки и пограничные случаи
| Ситуация | Поведение |
|---|---|
| Сумма не распознана | «Не расслышал сумму. Скажите, например: “100 тысяч на бензин”» |
| Сумма больше 100 млн сум | Запрос подтверждения: «Точно 150 000 000 сум?» [Да] [Нет, исправить] |
| Дата в будущем («завтра заплачу за свет») | Предложение создать **пункт плана-напоминание** вместо расхода |
| Голосовое длиннее 2 минут | Обрабатывается, но предупреждение о лимите минут |
| Лимит ИИ исчерпан | Сообщение о лимите и подсказка текстового формата «45000 такси» (работает без ИИ) |
| Шум или пустое аудио | «Не расслышал, повторите» |

### 6.7. Критерии приёмки
1. Фраза «Бензинга 100 минг сўм харажат қилдим» записывает 100 000 сум в «Бензин и авто» в ≥ 95% из 20 тестовых записей разными голосами.
2. Фраза с двумя расходами создаёт две записи.
3. «Исправь последнюю на 120 тысяч» меняет сумму последней записи.
4. Удаление голосом работает, «↩️ Вернуть» восстанавливает запись.
5. Исправленная пользователем категория применяется автоматически при следующей похожей фразе.
6. Запись голосом в чате появляется в «Кошельке» MA и сайта ≤ 3 с.
7. Время от отправки голосового до карточки — ≤ 6 с для записи до 15 с.

## 7. Требование 3. Задачи голосом: автоматический разбор, правка, перезапись

### 7.1. Цель
Руководитель (или сотрудник себе) диктует задачу. Система сама собирает её полностью: что сделать, кто делает, срок, время, длительность, приоритет, чек-лист, фото-отчёт, повтор. Ошибку можно исправить кнопками, текстом или новым голосом до отправки исполнителю.

### 7.2. Что извлекается из голоса

| Поле | Пример фразы | Результат |
|---|---|---|
| Название | «…подготовить отчёт по продажам…» | «Подготовить отчёт по продажам» |
| Исполнитель | «Мадине…», «Азизга…» | Мадина (поиск по команде с учётом падежей и уменьшительных форм) |
| Срок (дата) | «до пятницы», «ertaga», «послезавтра», «15 ноября» | Дата |
| Время срока | «до 15:00», «к обеду» (=13:00), «до конца дня» (=18:00) | Время |
| **Начало** (новое) | «начать в 10», «с понедельника» | Дата и время начала |
| **Длительность** (новое) | «на 2 часа», «займёт полдня» (=4 ч) | Минуты |
| Приоритет | «срочно», «важно», «tez», «shoshilinch» | Высокий |
| Чек-лист | «…сначала выгрузи из 1С, потом сверь, потом отправь» | 3 пункта |
| Фото-отчёт | «пришли фото», «с фото-отчётом» | Нужен фото-отчёт |
| Повтор | «каждый день», «по будням», «har dushanba» | Правило повтора |
| Напоминание | «напомни за час» | Напоминание за 60 мин до срока |
| Описание | Остальной смысловой текст | Подробности |

Несколько задач в одном голосовом («Мадине отчёт до 15, Азизу обзвон до завтра») дают несколько черновиков.

### 7.3. Черновик задачи (карточка в боте)
```
📝 Новая задача — проверьте:

«Подготовить отчёт по продажам за октябрь»
👤 Исполнитель: Мадина
📅 Срок: завтра, 2 ноября, до 15:00
⏱ Начало: завтра 10:00 · длительность 3 ч
⚡ Приоритет: высокий
📋 Чек-лист: 3 пункта
📸 Нужен фото-отчёт
🔁 Не повторяется
⚠️ У Мадины на завтра уже 7 ч задач — будет перегрузка (подробнее)

[✅ Поставить задачу]
[✏️ Исправить] [🎙 Перезаписать] [✖️ Отмена]
```
- Строка ⚠️ появляется, если проверка из Требования 6 нашла перегрузку или наложение.
- Поля, которые ИИ не смог определить, показываются как «не указано», и нажатие «Поставить» спрашивает недостающее. Обязательны только название и исполнитель. Остальное заполняется по умолчанию: срок — завтра до конца дня, приоритет — средний.

### 7.4. Правка черновика
**«✏️ Исправить»** открывает меню полей (кнопки):
`[Название] [Исполнитель] [Срок] [Время] [Начало/длительность] [Приоритет] [Чек-лист] [Фото-отчёт] [Повтор] [Описание] [« Назад]`

| Поле | Способ правки в боте |
|---|---|
| Название, описание | «Напишите или скажите новое название» → текст или голос |
| Исполнитель | Кнопки со списком команды (до 12, дальше «Ещё…»), «🙋 Себе» |
| Срок | Кнопки: «Сегодня», «Завтра», «Послезавтра», «Пт», «Через неделю», «📅 Другая дата» (ввод «15.11» или голосом) |
| Время | Кнопки: 10:00, 12:00, 15:00, 18:00, «Без времени», «Другое» |
| Начало и длительность | Кнопки длительности: 30 мин, 1 ч, 2 ч, 4 ч, день; начало — как время |
| Приоритет | Высокий / Средний / Низкий |
| Чек-лист | Список пунктов с ❌ для удаления, «➕ Добавить пункт» (текст или голос) |
| Фото-отчёт, повтор | Переключатели и выбор правила |

**Голосовая правка без меню:** пока черновик открыт (последний черновик пользователя, не старше 30 минут), голосовое или текст вида «нет, не Мадине, а Бехзоду», «перенеси на пятницу», «сделай не срочной» **применяется к черновику**, а не создаёт новую задачу. Бот обновляет карточку (`editMessageText`) и коротко подтверждает: «Исполнитель изменён на Бехзода».

**«🎙 Перезаписать»** — бот отвечает «Запишите голосовое заново» и ждёт новое голосовое. Оно полностью заменяет черновик (старая карточка помечается «Заменено ↓»).

**В Mini App** черновик открывается формой со всеми полями, предзаполненными ИИ. Есть кнопка «🎙 Надиктовать заново» и `MainButton` «Поставить задачу».

### 7.5. После постановки
- Исполнитель получает задачу с кнопками (Требование 8) и, если задано, чек-листом.
- Автор видит «✅ Задача поставлена — Мадина получила уведомление» и кнопку «Открыть в Орбите» (MA).
- Ошибку можно исправить и **после постановки**: «✏️ Изменить» в карточке автора, правки уходят исполнителю сообщением «🔄 Задача изменена: срок перенесён на пятницу».

### 7.6. Критерии приёмки
1. Фраза «Мадине до завтра в 15:00 подготовить отчёт по продажам, срочно, с фото» даёт черновик со всеми 5 полями без ошибок в ≥ 90% из 20 тестов.
2. Голосом «нет, не Мадине, а Бехзоду» исполнитель черновика меняется, новая задача не создаётся.
3. «Перезаписать» полностью заменяет черновик.
4. Каждое поле правится кнопками без ввода текста (кроме названия и описания).
5. Черновик, созданный в чате, можно открыть и поставить из MA (и наоборот), без дублей.
6. Время от голосового до черновика — ≤ 7 с для записи до 20 с.

## 8. Требование 4. Вопросы боту и напоминания по каждому пункту

### 8.1. Цель
Пользователь спрашивает голосом или текстом («Какие у меня планы на сегодня?», «Bugungi rejalarim nima?») и сразу получает полный список дел. На каждый пункт напоминание приходит в своё время.

### 8.2. Поддерживаемые вопросы

| Вопрос (примеры) | Ответ |
|---|---|
| «Какие у меня планы на сегодня?», «bugun nima qilishim kerak?» | Единый список на сегодня: задачи + пункты плана + привычки, отсортированы по времени |
| «Что у меня завтра?», «что на этой неделе?» | То же за день или неделю (по дням) |
| «Что горит?», «что просрочено?» | Просроченные задачи и задачи со сроком сегодня |
| «Что сделала Мадина сегодня?» (руководитель) | Выполненные и открытые задачи сотрудника |
| «Кто перегружен?» (руководитель) | Сотрудники с перегрузкой (Требование 6) |
| «Сколько я потратил вчера?» | См. Требование 2 |
| «Когда у меня свободное время завтра?» | Свободные окна между задачами в рабочем времени |

Если вопрос не распознан как одно из действий, ИИ отвечает коротко, опираясь только на данные пользователя в «Орбите». Выдумывать данные ИИ не должен.

### 8.3. Формат ответа «на сегодня»
```
🗓 Сегодня, 2 ноября — 6 дел

09:30  ✅ Открытие точки (чек-лист 3/3)
10:00  ▫️ Отчёт по продажам · до 15:00 · 🔔 за 30 мин
12:00  ▫️ Обед с партнёром (личное) · 🔔 в 11:45
15:00  ⚠️ Сверка оплат · до 18:00 — накладывается с отчётом
—      ▫️ Позвонить в банк (без времени)
🌙     💪 Чтение Корана · 🔔 21:00

Просрочено: 1 — «Обзвонить клиентов» (срок был вчера)

[🔔 Настроить напоминания] [🪐 Открыть в Орбите]
```
- У каждого пункта показано, **когда сработает напоминание** (или «без напоминания»).
- Кнопка «🔔 Настроить напоминания» открывает список пунктов с выбором времени напоминания для каждого: «за 10 / 15 / 30 / 60 мин», «в точное время», «выключить».

### 8.4. Напоминания по каждому пункту
1. **Задачи:** напоминание `remind_offset_min` до срока (или до начала, если задано начало). Значение по умолчанию берётся из настроек пользователя (сейчас «за 2 часа») и может быть переопределено для конкретной задачи.
2. **Пункты плана:** напоминание в указанное время или за N минут до него.
3. **Привычки:** в указанное время, если ещё не отмечена.
4. Напоминание — сообщение в боте с кнопками действий (Требование 8). В MA и на сайте — всплывающее уведомление (если открыт) и бейдж.
5. Повторная отправка одного и того же напоминания исключена (таблица `reminders` со статусами, см. раздел 18).

### 8.5. Критерии приёмки
1. Вопрос голосом «Bugungi rejalarim nimadan iborat?» возвращает список, совпадающий с разделом «Сегодня» в MA.
2. В ответе у каждого пункта указано время напоминания.
3. Изменение времени напоминания в ответе бота отражается в MA и на сайте, и напоминание приходит в новое время.
4. Ответ приходит ≤ 4 с после текстового вопроса и ≤ 7 с после голосового.

## 9. Требование 5. Задачи в виде диаграммы Ганта

### 9.1. Цель
Видеть задачи на временной шкале: кто чем занят, что накладывается, что сдвигается. Переносить задачи перетаскиванием.

### 9.2. Данные для Ганта
У задачи появляются поля:
- `start_at` — начало (дата и время, необязательно);
- `duration_min` — длительность (необязательно);
- срок `due` + `due_time` (уже есть).

**Правило отображения:**
- Если есть начало и длительность — полоса от начала до начала + длительность. Срок отображается маркером ◆.
- Если есть только срок — полоса от даты создания (или начала дня срока, если длительность задана) до срока.
- Если задача без времени — полоса на весь день срока.

### 9.3. Виды и масштабы
| Масштаб | Шкала | Для чего |
|---|---|---|
| День | По часам (рабочее время 08:00–20:00, можно расширить) | Распорядок дня сотрудника, наложения |
| Неделя | По дням с делением на половины дня | Основной вид руководителя |
| Месяц | По дням | Долгие задачи и повторы |

**Группировка строк:** по сотрудникам (по умолчанию для руководителя), по отделам, без группировки (для сотрудника — только свои задачи).

### 9.4. Элементы диаграммы
- **Цвет полосы — статус:** новая, в работе, на проверке, выполнена. Просроченная — красная с штриховкой.
- **Иконки на полосе:** 📸 фото-отчёт, 📋 чек-лист (с прогрессом), 🔁 повтор, ⏳ запрошено продление.
- **Линия «сейчас»** (вертикальная, обновляется раз в минуту).
- **Наложения:** у пересекающихся задач одного человека — красная рамка пересечения (Требование 6).
- **Линия загрузки** под строкой сотрудника: занятые часы в день; день красный, если загрузка больше 100%.
- **Зависимости** (необязательная часть, этап 2): стрелка «задача B начинается после A». При переносе A предлагается сдвинуть B.

### 9.5. Действия
| Действие | Кто может | Результат |
|---|---|---|
| Перетащить полосу по горизонтали | Автор задачи, руководство | Перенос начала и срока, исполнитель получает «🔄 Срок перенесён на …» |
| Потянуть за край полосы | Автор, руководство | Изменение длительности или срока |
| Перетащить в строку другого сотрудника | Автор, руководство | Смена исполнителя (с подтверждением) |
| Нажать на полосу | Все, кто видит задачу | Карточка задачи |
| Двойной клик или долгий тап по пустому месту | Руководитель (себе — любой) | Новая задача с заполненным временем и исполнителем |

На телефоне (MA): вместо перетаскивания — долгий тап → меню «Перенести на…» / «Изменить длительность». Шкала прокручивается горизонтально, имена сотрудников закреплены слева.

### 9.6. Синхронизация
Перенос на Ганте вызывает ту же функцию, что и смена срока в карточке. Событие `task.updated` перерисовывает Гант у всех, кто его открыл.

### 9.7. Производительность
Плавная работа (≥ 50 кадров/с при прокрутке) при 50 сотрудниках и 1 000 задачах в видимом периоде. Отрисовка — Canvas или виртуализированный DOM, без внешних тяжёлых библиотек (допускается лёгкая библиотека до 60 КБ gzip после согласования).

### 9.8. Критерии приёмки
1. Гант доступен на сайте и в MA в масштабах «день / неделя / месяц».
2. Перетаскивание переносит задачу, исполнитель получает уведомление, сайт и MA обновляются ≤ 3 с.
3. Сотрудник не может перетаскивать задачи, которые ставил не он (кнопки и перетаскивание недоступны, сервер возвращает 403).
4. Пересекающиеся задачи одного человека подсвечены.
5. На телефоне шкала прокручивается без горизонтальной прокрутки всей страницы.

## 10. Требование 6. Предупреждения о перегрузке и наложении задач

### 10.1. Цель
Не допускать ситуации, когда у сотрудника слишком много задач или задачи идут одновременно. Предупреждать **до** постановки задачи и при изменениях.

### 10.2. Правила проверки
| Код | Правило | Порог по умолчанию | Настраивается |
|---|---|---|---|
| `OVERLAP` | Две и более задачи (или задача и пункт плана) одного человека пересекаются по времени | Пересечение ≥ 15 мин | Да |
| `DAY_HOURS` | Сумма длительностей задач на день больше рабочего времени | Больше 8 ч | Да (рабочие часы сотрудника) |
| `DAY_COUNT` | Число открытых задач со сроком в один день | Больше 6 | Да |
| `OPEN_TOTAL` | Всего открытых задач у человека | Больше 15 | Да |
| `HIGH_PRIO` | Задач с высоким приоритетом на один день | Больше 3 | Да |
| `OFF_HOURS` | Задача назначена на выходной или вне рабочего времени сотрудника | — | Да (график сотрудника) |

**Длительность задачи без указанной длительности** для расчёта: по умолчанию 1 ч. Можно включить оценку ИИ по названию («Подготовить отчёт» ≈ 2 ч) — с пометкой «примерно».

### 10.3. Когда проверяется
1. При создании черновика (голос, текст, форма) — предупреждение прямо в черновике (строка ⚠️) **до** нажатия «Поставить».
2. При переносе на Ганте и смене срока или исполнителя.
3. Раз в день в утреннем отчёте руководителю: «Перегружены сегодня: Азиз (9,5 ч), Мадина (наложение 15:00–16:00)».
4. Предупреждение **не блокирует** действие: руководитель может поставить задачу. Кнопки в предупреждении:
   - «Всё равно поставить»;
   - «Перенести на свободное время» — система предлагает ближайшее свободное окно;
   - «Назначить другому» — предлагаются 3 наименее загруженных сотрудника из той же команды.

### 10.4. Где видно
- **Бот:** строка ⚠️ в черновике и отдельное сообщение руководителю при возникновении наложения (не чаще одного сообщения в час на сотрудника, без спама).
- **MA и сайт:**
  - значок ⚠️ на задаче и в строке сотрудника на Ганте;
  - блок «Перегрузка» в «Командном центре»;
  - тост при сохранении.
- **Сотрудник** видит предупреждение о своих наложениях («У вас в 15:00 две задачи») с кнопкой «Попросить перенести» (уходит автору как «Нужно больше времени» с пометкой «наложение»).

### 10.5. Критерии приёмки
1. Создание задачи на время, занятое другой задачей того же сотрудника, показывает ⚠️ в черновике с указанием конфликтующей задачи.
2. «Перенести на свободное время» предлагает окно, в котором нет пересечений.
3. Пороги меняются в настройках компании, и проверка учитывает новые значения.
4. Повторные предупреждения об одном и том же наложении не приходят чаще раза в час.

## 11. Требование 7. Ежедневный утренний отчёт

### 11.1. Цель
Каждое утро в выбранное время пользователь получает отчёт о вчерашнем дне: расходы по категориям, выполненные и невыполненные задачи. Тот же отчёт доступен в MA и на сайте.

### 11.2. Настройка
- Время отправки задаёт сам пользователь (по умолчанию 08:00): в боте («⚙️ Настройки → Утренний отчёт»), в MA и на сайте. Значение одно и то же везде (`members.settings.morning` → переносится в настройки пользователя `users.settings.report_time`).
- Отдельно включаются блоки: «Расходы», «Мои задачи», «Команда» (для руководителя), «План на сегодня».
- Можно выключить отчёт в выходные.

### 11.3. Содержание отчёта (бот)
```
☀️ Доброе утро, Дилшод! Отчёт за вчера, 1 ноября

👛 РАСХОДЫ: 385 000 сум (12 операций)
  ⛽ Бензин и авто ......... 150 000
  🍽 Кафе и рестораны ....... 120 000
  🛒 Продукты ................ 85 000
  🚕 Такси ................... 30 000
  Доходы: 0 · С начала месяца: 2 835 000 (лимит 4 000 000 — 71%)
  ⚠️ Кафе: 92% лимита месяца

✅ ЗАДАЧИ: выполнено 5 из 7
  ✔️ Отчёт по продажам (вовремя)
  ✔️ Сверка оплат (с опозданием 2 ч)
  ✖️ Обзвонить клиентов — перенести?
  ✖️ Акт сверки — перенести?

👥 КОМАНДА (руководитель): вовремя 82% · просрочено 2
  Лучший: Нилуфар (100%) · Внимание: Азиз (2 просрочки)

🗓 СЕГОДНЯ: 6 дел, первое в 09:30 — «Открытие точки»

[📊 Открыть отчёт] [➡️ Перенести невыполненные на сегодня]
```
- **«➡️ Перенести невыполненные на сегодня»** переносит свои невыполненные задачи (только где пользователь автор или исполнитель с правом переноса) и пункты плана. Для чужих задач кнопка отправляет запрос автору.
- У каждой невыполненной задачи — кнопки «Перенести» (меню дат) и «Отменить» (для автора).

### 11.4. Отчёт в MA и на сайте
- Раздел **«Отчёты»**: выбор даты (по умолчанию вчера), те же блоки с графиками:
  - кольцо расходов по категориям;
  - список задач с отметками вовремя / с опозданием / не выполнено;
  - дисциплина команды.
- Отчёт за любой прошедший день формируется по данным (не только из отправленного сообщения).
- Кнопка в сообщении бота открывает этот отчёт в MA (`#report=2026-11-01`).

### 11.5. Синхронность
- Отчёт строится одной серверной функцией `buildDailyReport(userId, date)`. Бот, MA и сайт показывают один и тот же результат.
- Если после отправки отчёта данные за вчера изменились (кто-то записал вчерашний расход), в MA и на сайте отчёт обновляется. Сообщение в боте не редактируется, но кнопка «Открыть отчёт» показывает актуальную версию.

### 11.6. Критерии приёмки
1. Отчёт приходит в выбранное время ±1 мин, ровно один раз в день (без дублей при перезапуске сервера).
2. Суммы по категориям совпадают с «Кошельком» за этот день.
3. Список выполненных и невыполненных задач совпадает с разделом задач.
4. Изменение времени отчёта в MA сразу применяется к боту и сайту.
5. «Перенести невыполненные на сегодня» переносит задачи, и это видно на Ганте и в списках ≤ 3 с.

## 12. Требование 8. Напоминания о приближении срока с кнопками действий

### 12.1. Цель
Перед сроком задачи (или временем пункта плана) приходит напоминание с кнопками. Нажатие кнопки в боте мгновенно меняет состояние на сайте и в MA, и наоборот.

### 12.2. Сообщение напоминания
```
⏰ Через 30 минут срок: «Отчёт по продажам»
до 15:00 · от Дилшода · чек-лист 2/3

[✅ Сделал] [👀 Видел, помню]
[⏰ Напомнить позже ▾] [⏳ Нужно больше времени]
[🪐 Открыть]
```

### 12.3. Кнопки и действия

| Кнопка | Действие | Где отражается |
|---|---|---|
| **✅ Сделал** | Задача → «Выполнено» (или запрос фото, если нужен фото-отчёт). Пункт плана → отмечен | Автору — уведомление; задача на сайте и в MA — выполнена; кнопки сообщения → «✅ Выполнено» |
| **👀 Видел, помню** (Esladim) | Фиксируется «прочитано в …», повторные напоминания по этому сроку отключаются (кроме «срок истёк») | Автор видит «👀 Мадина видела напоминание в 14:31» в карточке задачи |
| **⏰ Напомнить позже** | Подменю: «через 15 мин», «через 1 час», «через 3 часа», «завтра в 9:00», «другое время» | Новое время напоминания видно в карточке задачи на сайте и в MA |
| **⏳ Нужно больше времени** | Запрос автору с кнопками +2 ч / +1 день / +3 дня (уже есть в 1.x) | Блок «Требует решения» у руководителя |
| **🙅 Не напоминать** (в подменю «позже») | Отключить напоминания по этому пункту | Переключатель «Напоминание» в карточке выключается |
| **🪐 Открыть** | Открывает задачу в MA | — |

### 12.4. Расписание напоминаний (по умолчанию, настраивается)
| Момент | Сообщение |
|---|---|
| За N минут до срока (N из настроек: 15/30/60/120) | «⏰ Через N минут срок…» |
| В момент срока, если не выполнено | «🔔 Срок наступил…» |
| Через 1 час после срока (только исполнителю, один раз) | «🔴 Срок истёк…» (уже есть в 1.x) + автору кнопки продления |
| Пункт плана | В указанное время или за N минут |

### 12.5. Синхронизация кнопок (обязательное требование)
1. Нажатие в боте → серверная функция → событие → сайт и MA обновляются ≤ 3 с.
2. Отметка «Сделал» на сайте или в MA → сервер находит **все отправленные сообщения бота по этой задаче** (`tg_msgs`, у получателей) и редактирует их кнопки на «✅ Выполнено». Ожидающие напоминания по задаче отменяются.
3. Перенос срока (Гант, карточка, бот) → ожидающие напоминания пересчитываются на новый срок. Старые кнопки «Сделал» продолжают работать, а «Напомнить позже» в старом сообщении применяется к новому сроку.
4. Повторное нажатие уже выполненного действия отвечает всплывающим «Уже отмечено» без изменений.

### 12.6. Критерии приёмки
1. Напоминание приходит за выбранное время ±1 мин.
2. «Напомнить через 15 мин» приводит к повторному напоминанию через 15 ± 1 мин.
3. «Сделал» в боте → задача выполнена в MA и на сайте ≤ 3 с.
4. «Сделал» на сайте → кнопки в сообщении бота меняются ≤ 5 с, последующие напоминания не приходят.
5. «Видел, помню» отображается автору в карточке задачи.

## 13. Требование 9. Автопланирование дня

### 13.1. Цель
Система сама раскладывает задачи и личные дела по свободному времени дня с учётом сроков, приоритетов, длительности и рабочего времени. Когда что-то меняется (новая срочная задача, перенос, опоздание), день пересобирается.

### 13.2. Что входит в планирование
- Открытые задачи пользователя со сроком сегодня или ранее (просроченные), а также задачи со сроком в ближайшие 3 дня, если у них нет времени начала.
- Пункты плана **без** точного времени.
- Задачи и пункты плана с **фиксированным временем** (встреча в 12:00, задача с `start_at`) не двигаются. Это «якоря», вокруг которых строится план.
- Рабочее время пользователя (`members.work_hours`), перерывы (по умолчанию обед 13:00–14:00, настраивается) и время намаза, если пользователь включил его в настройках (как неподвижные блоки по расписанию для Ташкента).

### 13.3. Алгоритм (правила)
1. **Порядок важности:**
   1. просроченные;
   2. высокий приоритет со сроком сегодня;
   3. остальные со сроком сегодня (раньше срок — раньше в плане);
   4. высокий приоритет на ближайшие дни;
   5. остальные.
2. **Длительность:** указанная, иначе оценка (1 ч по умолчанию или оценка ИИ, помеченная «≈»).
3. **Размещение:** каждая задача ставится в самое раннее свободное окно, которое заканчивается до её срока. Если не помещается до срока — ставится в конец дня с пометкой ⚠️ «не успевает к сроку».
4. **Деление:** задачу длиннее 2 ч разрешено делить на части не короче 30 мин (по умолчанию выключено, включается в настройках).
5. **Буфер** между задачами — 10 мин (настраивается: 0 / 5 / 10 / 15).
6. Если всё не помещается в рабочий день — остаток уходит в блок «Не помещается сегодня» с кнопками «Перенести на завтра» и «Попросить продлить срок».
7. Матрица «важно / срочно» (Требование 10), если пользователь её заполнил, имеет приоритет над правилом 1: квадрант «важно и срочно» → «важно, не срочно» → «срочно, не важно» → «не важно, не срочно».

Алгоритм работает **на сервере без ИИ** (детерминированный). ИИ используется только для оценки длительности задач без длительности (по желанию).

### 13.4. Когда строится план
| Событие | Действие |
|---|---|
| Утренний отчёт (Требование 7) | В блоке «Сегодня» показывается предложенный план дня |
| Кнопка «🪄 Спланировать мой день» (бот, MA, сайт) | Построение плана |
| Голосом: «Спланируй мне день», «kunimni rejalashtir» | Построение плана |
| Новая задача со сроком сегодня, перенос, «Сделал» раньше времени | Предложение «🔄 Пересобрать день?» (без самовольного изменения) |
| Пользователь не начал задачу в запланированное время (задача не в статусе «В работе» через 15 мин) | Предложение сдвинуть остаток дня |

### 13.5. Подтверждение
План — это **предложение**. Он не меняет данные, пока пользователь не нажмёт «✅ Принять план».
- **Бот:**
  ```
  🪄 План на сегодня (рабочий день 09:00–18:00)

  09:00–09:30  Открытие точки (чек-лист)
  09:40–11:40  Отчёт по продажам · до 15:00 · ≈2 ч
  11:50–12:20  Позвонить в банк
  13:00–14:00  — обед —
  14:00–15:00  Сверка оплат · до 18:00
  15:10–15:35  🍅 Фокус: письмо партнёру
  ⚠️ Не помещается: «Акт сверки» (≈3 ч)

  [✅ Принять план] [✏️ Изменить в Орбите] [➡️ Неуместившееся на завтра]
  ```
- **MA и сайт:** вид «День» на Ганте с предложенными полосами (полупрозрачными). Полосы можно перетащить до принятия. Кнопка «Принять план».
- После принятия у задач и пунктов заполняются `start_at` и `duration_min`, и создаются напоминания (Требование 8) на начало каждого блока.
- Задачи **других людей не меняются**: план строится только из задач, где пользователь исполнитель, и его личных дел. Перенос срока чужой задачи — только через «Попросить продлить срок».

### 13.6. Для руководителя
- Кнопка «Спланировать день сотруднику» — предложение отправляется сотруднику в бот на принятие («Руководитель предложил план на день»).
- Руководитель видит, принят ли план, на Ганте в виде «День».

### 13.7. Критерии приёмки
1. План не ставит задачу в занятое время и вне рабочего времени.
2. Задачи с фиксированным временем не сдвигаются.
3. Просроченные и срочные задачи стоят раньше остальных.
4. Задача, которая не успевает к сроку, помечена ⚠️.
5. До нажатия «Принять план» данные не меняются. После принятия время задач видно на Ганте в MA и на сайте ≤ 3 с, напоминания созданы.
6. Построение плана на 30 задач — ≤ 1 с.

## 14. Требование 10. Матрица «важно / срочно» (Эйзенхауэр)

### 14.1. Цель
Помочь руководителю и сотруднику решить, что делать первым, разложив задачи и личные дела по четырём квадрантам.

### 14.2. Квадранты
| Квадрант | Смысл | Что предлагает система |
|---|---|---|
| **I. Важно и срочно** | Сделать сейчас | Ставится первым в автоплане, напоминание включено |
| **II. Важно, не срочно** | Запланировать | Предложение выбрать время в автоплане на неделю |
| **III. Срочно, не важно** | Поручить | Кнопка «Поручить» → черновик задачи сотруднику (Требование 3) |
| **IV. Не важно, не срочно** | Отложить или удалить | Кнопки «Отложить на неделю» и «Удалить» |

### 14.3. Как задача попадает в квадрант
1. **Автоматически** по правилам (пользователь может переставить вручную):
   - **срочно** — срок сегодня, завтра или просрочено;
   - **важно** — высокий приоритет, или задача от руководителя компании, или пользователь отметил «⭐ важно».
2. **Вручную:**
   - перетаскивание карточки между квадрантами (сайт, MA);
   - кнопки «Квадрант» в карточке задачи в боте;
   - голосом: «отчёт для банка — важно, но не срочно».
3. Ручной выбор сохраняется (`tasks.quadrant`, `plan_items.quadrant`) и больше не перезаписывается автоматикой, пока пользователь не нажмёт «Сбросить на авто».
4. Квадрант — **личный взгляд пользователя**. У исполнителя и руководителя квадрант одной задачи может быть разным (хранится по пользователю — таблица `user_task_meta`).

### 14.4. Где отображается
- **Сайт и MA:** вкладка «Матрица» в разделах «Задачи» и «Мои планы». 4 квадранта сеткой 2×2, на телефоне — 4 сворачиваемых блока. В каждой карточке: название, срок, исполнитель (у руководителя), кнопка «Сделал».
- **Бот:** команда и вопрос «Что важно сегодня?» → список квадранта I и количество в остальных, кнопки «Показать II / III / IV».
- **Утренний отчёт:** строка «Важно и срочно: 3 задачи».

### 14.5. Критерии приёмки
1. Задача с высоким приоритетом и сроком сегодня автоматически попадает в квадрант I.
2. Перетаскивание между квадрантами сохраняется и видно в MA и на сайте ≤ 3 с.
3. Ручной квадрант не сбрасывается автоматически.
4. «Поручить» из квадранта III открывает черновик задачи с заполненным названием.
5. Квадрант руководителя не влияет на квадрант исполнителя.

## 15. Требование 11. Таймер фокуса (Pomodoro)

### 15.1. Цель
Сосредоточенная работа над одной задачей короткими отрезками с перерывами и учёт, сколько фокус-времени ушло на задачу.

### 15.2. Параметры (настраиваются пользователем)
| Параметр | По умолчанию | Варианты |
|---|---|---|
| Длительность фокуса | 25 мин | 15 / 25 / 45 / 50 / 90 |
| Короткий перерыв | 5 мин | 3–15 |
| Длинный перерыв | 15 мин | 10–30 |
| Длинный перерыв после | 4 «помидоров» | 2–6 |
| Автостарт перерыва и следующего фокуса | Выкл | Вкл / Выкл |
| Звук в MA и на сайте | Вкл | Вкл / Выкл |
| Режим «Не беспокоить» на время фокуса | Вкл | Вкл / Выкл |

### 15.3. Запуск и управление
- **Из задачи или пункта плана** (сайт, MA, бот): кнопка «🍅 Фокус». Задача переходит в статус «В работе», если была «Новая».
- **Голосом:** «включи фокус на отчёт на 45 минут», «pomodoro boshla».
- **Без задачи:** «🍅 Свободный фокус» с необязательной подписью.
- Во время фокуса **в MA и на сайте** — крупный экран таймера:
  - название задачи и чек-лист;
  - кнопки «⏸ Пауза», «⏹ Завершить», «✅ Задача выполнена»;
  - номер помидора («2 из 4»).
- **В боте** — одно закреплённое сообщение `🍅 Фокус: «Отчёт по продажам» — осталось 18 мин` с кнопками «⏸», «⏹», «✅ Сделал». Сообщение обновляется раз в минуту, а не каждую секунду (ограничения Telegram).
- **Окончание фокуса:** сообщение в боте «🍅 Фокус завершён (25 мин). Перерыв 5 минут» и звук в MA и на сайте. После перерыва: «Продолжить фокус?» [▶️ Ещё 25 мин] [✅ Задача выполнена] [⏹ Хватит].

### 15.4. Синхронизация
- Один активный таймер на пользователя. Состояние хранится на сервере (`focus_sessions`: старт, план, пауза, статус), а не в браузере.
- Таймер, запущенный в боте, виден в MA и на сайте с тем же оставшимся временем, и наоборот. Пауза в любом клиенте ставит паузу везде ≤ 3 с.
- Если MA закрыт, окончание фокуса приходит сообщением в бот (сервер сам отслеживает время окончания через планировщик напоминаний, тип `focus_end`).

### 15.5. «Не беспокоить»
Во время фокуса уведомления о **новых задачах, комментариях и сводках** с низким и средним приоритетом откладываются и приходят одним сообщением после окончания фокуса.

Срочные уведомления приходят сразу:
- задача с высоким приоритетом;
- срок истекает в ближайшие 15 мин;
- руководитель отметил «срочно».

### 15.6. Статистика
- В карточке задачи: «🍅 3 фокуса · 1 ч 15 мин».
- В «Мои планы»: фокус-время за день и неделю, серия дней с фокусом.
- В утреннем отчёте (необязательный блок): «Вчера в фокусе: 2 ч 30 мин (6 🍅)».
- Руководитель видит **только суммарное** фокус-время сотрудника по его задачам (по желанию сотрудника, по умолчанию выключено — это личный инструмент).

### 15.7. Критерии приёмки
1. Фокус, запущенный в боте, показывает то же оставшееся время в MA и на сайте (±5 с).
2. Пауза и завершение синхронизируются ≤ 3 с.
3. Окончание фокуса приходит в бот, даже если MA и сайт закрыты (±1 мин).
4. Во время фокуса несрочные уведомления не приходят, а после окончания приходят одним сообщением.
5. Фокус-время учитывается в карточке задачи и статистике.

## 16. Требование 12. Фото чека → расход

### 16.1. Цель
Пользователь фотографирует чек (или пересылает скриншот оплаты Payme, Click, Uzum, банковское SMS) — расход записывается автоматически: сумма, магазин, дата, категория.

### 16.2. Источники
| Источник | Как приходит |
|---|---|
| Фото бумажного чека | Фото в чат бота или кнопка «📷 Чек» в «Кошельке» MA (камера телефона) |
| Скриншот оплаты (Payme, Click, Uzum Bank, банковское приложение) | Изображение в бота или загрузка в MA и на сайте |
| Фискальный чек с QR-кодом (ОФД, soliq.uz) | Фото: система находит QR-код и берёт данные из него (сумма, дата, продавец, ИНН) |
| Пересланное SMS или текст уведомления банка | Текст в бота («Oплата 120 000 UZS KORZINKA…») |

### 16.3. Что извлекается
- **Итоговая сумма** (не промежуточные строки) и валюта.
- **Дата и время** покупки (если на чеке; иначе — сегодня).
- **Продавец** («Korzinka», «Makro», «UzAuto Motors АЗС») → заметка.
- **Категория:** по продавцу и позициям (магазин продуктов → «Продукты», АЗС → «Бензин и авто», аптека → «Здоровье»). Используются правила самообучения из Требования 2 (`wallet_rules`) по названию продавца.
- **Позиции чека** (необязательно, этап 2). При наличии разбиение одного чека на несколько категорий: «Продукты 180 000 + Хозтовары 45 000» — с кнопкой «Разделить по категориям».
- **Способ оплаты** (наличные / карта), если виден.

### 16.4. Обработка
1. Изображение → распознавание: ИИ-модель с поддержкой изображений (тот же поставщик ИИ, что для голоса). Ей передаётся список категорий и требование вернуть JSON `{amount, currency, date, merchant, category, items[], confidence}`.
2. Если на фото найден фискальный QR-код — данные из QR имеют приоритет над распознаванием текста. Сумма и дата сверяются.
3. **Подтверждение:**
   - если `confidence ≥ 0,8` — расход сохраняется сразу, и приходит карточка с кнопками «✏️ Изменить», «🏷 Категория», «↩️ Отменить» (как в Требовании 2);
   - если ниже — карточка-черновик «Проверьте» с кнопкой «✅ Сохранить».
   ```
   🧾 Чек распознан
   Korzinka · 1 ноября, 19:42
   Сумма: 225 400 сум → 🛒 Продукты
   [✅ Сохранить] [✏️ Изменить] [🏷 Категория] [✖️ Отмена]
   ```
4. **Фото чека прикрепляется к записи** (хранится `file_id` Telegram или файл в хранилище) и видно в «Кошельке» MA и на сайте по нажатию на запись.
5. **Дубли:** если запись с той же суммой, датой (±1 день) и продавцом уже есть — предупреждение «Похоже, этот чек уже записан» [Всё равно записать] [Отмена].

### 16.5. Ошибки
| Ситуация | Поведение |
|---|---|
| Фото размыто, сумма не найдена | «Не удалось прочитать сумму. Сфотографируйте ближе или скажите сумму голосом» |
| На фото не чек | «Это не похоже на чек» + предложение записать вручную |
| Несколько чеков на одном фото | Распознаётся каждый, черновик на каждый |
| Чек в долларах или рублях | Пересчёт в сумы по курсу ЦБ (Требование 2, п. 6.3) |
| Фото к задаче (ответом на сообщение о задаче) | Остаётся фото-отчётом задачи (поведение 1.x), не расходом |

**Разграничение с фото-отчётом:** фото **ответом** на сообщение о задаче — фото-отчёт. Фото **без ответа**, или с подписью «чек», или через кнопку «📷 Чек» — расход. Если неясно (фото без подписи, а у пользователя есть задача, ждущая фото-отчёт) — бот спрашивает: [🧾 Это чек] [📸 Отчёт по задаче «…»].

### 16.6. Лимиты
Распознавание чека расходует лимит ИИ: 1 чек = 1 сообщение ИИ. Лимит по тарифу (раздел о тарифах 1.x) не меняется.

### 16.7. Критерии приёмки
1. На наборе из 30 реальных чеков (Korzinka, Makro, АЗС, аптеки, кафе, скриншоты Payme и Click):
   - сумма распознаётся верно в ≥ 95%;
   - дата — в ≥ 90%;
   - категория — в ≥ 85%.
2. Фискальный QR-код считывается, и данные из него используются.
3. Фото чека доступно в записи кошелька на сайте и в MA.
4. Повторная отправка того же чека вызывает предупреждение о дубле.
5. Фото ответом на сообщение о задаче не превращается в расход.
6. От отправки фото до карточки — ≤ 8 с.

## 17. Требование 13. Регулярные платежи

### 17.1. Цель
Не забывать об обязательных платежах (аренда, интернет, связь, коммуналка, кредит, подписки, зарплата водителю) и записывать их в кошелёк в один клик.

### 17.2. Создание регулярного платежа
| Поле | Пример |
|---|---|
| Название | «Аренда офиса» |
| Сумма | 6 000 000 сум (или «примерно» для коммуналки — тогда сумма уточняется при оплате) |
| Категория | «Дом и коммуналка» |
| Тип | Расход (или регулярный доход: зарплата, аренда от жильца) |
| Периодичность | Ежемесячно (число месяца), еженедельно (день недели), ежегодно (дата), каждые N дней |
| Дата следующего платежа | 5 ноября |
| Напоминание | За 3 дня и в день платежа (настраивается: за 1 / 3 / 7 дней) |
| Способ записи | «Спрашивать» (по умолчанию) или «Записывать автоматически» |
| Окончание | Без окончания / до даты / N платежей (кредит на 12 месяцев) |

**Способы создания:**
- в «Кошельке» MA и на сайте — кнопка «➕ Регулярный платёж»;
- голосом: «каждый месяц 5-го аренда 6 миллионов», «har oyning 10-sida internet 150 ming»;
- **автоподсказка:** если система видит три похожих расхода с интервалом около месяца (та же категория и продавец, сумма ±10%), она предлагает: «Похоже, “Интернет 150 000” — ежемесячный платёж. Сделать регулярным?» [Да] [Нет].

### 17.3. Напоминание и запись
```
📅 Через 3 дня, 5 ноября — платёж «Аренда офиса»
6 000 000 сум · 🏠 Дом и коммуналка
[🔔 Напомнить в день платежа]
```
```
💳 Сегодня платёж «Аренда офиса» — 6 000 000 сум
[✅ Оплачено — записать] [✏️ Другая сумма] [⏰ Завтра] [⏭ Пропустить этот раз]
```
| Кнопка | Действие |
|---|---|
| ✅ Оплачено — записать | Расход записывается с датой оплаты, следующий платёж сдвигается на период |
| ✏️ Другая сумма | Ввод суммы текстом или голосом → запись |
| ⏰ Завтра | Напомнить завтра (не больше 5 переносов, потом — «просрочен») |
| ⏭ Пропустить | Без записи, следующий платёж — по графику |

- **Автоматическая запись:** при выборе «Записывать автоматически» расход создаётся в день платежа в 09:00 с сообщением «Записан регулярный платёж» и кнопкой «↩️ Отменить».
- **Просрочка:** если платёж не отмечен 3 дня — красная метка в «Кошельке» и одно напоминание.

### 17.4. Отображение
- **Кошелёк (MA и сайт):**
  - блок **«Ближайшие платежи»** на 30 дней: название, дата, сумма, статус (ожидает / оплачен / просрочен);
  - **итог обязательных платежей в месяц**;
  - **«Свободные деньги после обязательных»** = доходы месяца − расходы месяца − неоплаченные регулярные платежи до конца месяца.
- **Утренний отчёт:** строка «📅 Платежи на этой неделе: Аренда (5 ноября) 6 000 000».
- **Календарь и Гант** (вид «Месяц»): платежи отображаются маркерами 💳 в личном виде пользователя (не видны руководителю и команде).

### 17.5. Приватность
Регулярные платежи — часть личного кошелька. Их видит только владелец. Руководитель и коллеги не видят их ни в каких разделах.

### 17.6. Синхронизация
«Оплачено» в боте → расход в «Кошельке» MA и сайта, статус платежа «оплачен» ≤ 3 с. Отметка оплаты на сайте отменяет ожидающее напоминание в боте и меняет кнопки отправленного сообщения на «✅ Оплачено».

### 17.7. Критерии приёмки
1. Голосовая фраза «каждый месяц 5-го аренда 6 миллионов» создаёт регулярный платёж с верными полями.
2. Напоминания приходят за выбранное число дней и в день платежа в 09:00 (±1 мин).
3. «Оплачено — записать» создаёт расход и сдвигает дату следующего платежа на период.
4. Автоматическая запись создаёт расход ровно один раз.
5. Автоподсказка срабатывает после трёх похожих ежемесячных расходов.
6. Регулярные платежи не видны другим пользователям (тест прав доступа).

## 21. Безопасность и доступ

1. Проверка подписи `initData` для каждого входа из MA (раздел 5.3).
2. Права:
   - сотрудник видит и меняет только свои задачи и личные данные;
   - руководитель — задачи своей ветки подчинения;
   - руководство компании — всё в компании;
   - **кошелёк и личные планы видит только владелец** — никто, включая руководителя.
3. Все кнопки бота проверяют, что нажал именно тот пользователь, которому адресовано действие.
4. Аудиофайлы не хранятся после распознавания. Хранится только текст расшифровки в черновике (30 дней).
5. Данные, передаваемые в ИИ: только текст сообщения, имена команды и названия открытых задач пользователя. Финансовые данные других людей не передаются. Фото чеков передаются в ИИ только для распознавания, и поставщик ИИ не использует их для обучения (настройка API без хранения данных).
8. **Фото чеков и регулярные платежи** — личные данные: доступ только владельцу. Ссылки на изображения чеков выдаются только авторизованному владельцу (`GET /api/receipts/:id/file`), не публично. Срок хранения изображений чеков — 12 месяцев, затем удаляются (сумма и данные записи остаются).
9. **Фокус-статистика** по умолчанию личная, руководителю видна только при включённой настройке сотрудника.
6. Ограничение частоты: не более 30 голосовых в минуту на пользователя, не более 10 запросов в секунду к API на сессию.
7. Ключи (BOT_TOKEN, OPENAI_API_KEY, ключи Payme/Click) хранятся только в переменных окружения Railway.

## 22. Тестирование и критерии приёмки

### 22.1. Виды тестов
1. **Автотесты API** (расширение текущего набора из 71+ проверок): каждый новый метод, права, конфликты версий.
2. **Тесты голоса:** набор из **100 эталонных голосовых** — 50 на русском, 40 на узбекском, 10 смешанных; разные голоса, шум улицы, машина. Метрики:
   - сумма и категория расхода — ≥ 95%;
   - исполнитель и срок задачи — ≥ 90%;
   - вопрос «что на сегодня» — ≥ 95%.
3. **Тесты синхронизации:** сценарии «действие в клиенте A → проверка в B и C» для каждой кнопки (матрица 3 × 3 клиентов × 8 действий).
4. **Тесты планировщика:** напоминания, отложенные напоминания, утренний отчёт; перезапуск сервера посреди отправки — без дублей и пропусков.
5. **Ручное тестирование MA** на iPhone, Android и Telegram Desktop.
6. **Нагрузочный тест:** 100 голосовых в минуту, 1 000 одновременных SSE-подключений.
7. **Тесты автоплана:** набор из 20 сценариев дня (якоря, просрочки, не помещается, обед, намаз, деление длинных задач). Проверяется, что нет пересечений и выхода за рабочее время, а порядок соблюдает правила 13.3.
8. **Тесты чеков:** набор из 30 реальных чеков и скриншотов (Korzinka, Makro, АЗС, аптеки, кафе, Payme, Click, Uzum, фискальные QR). Метрики — по 16.7.
9. **Тесты фокуса:** синхронизация таймера между тремя клиентами, окончание при закрытом MA, перезапуск сервера во время фокуса.
10. **Тесты регулярных платежей:** месячные даты 29–31 в коротких месяцах, перенос «Завтра» пять раз, автозапись без дублей, автоподсказка.

### 22.2. Приёмка
Работа принимается, когда:
- выполнены все критерии приёмки разделов 5–17;
- автотесты проходят на 100%;
- метрики голоса достигнуты на эталонном наборе;
- заказчик проверил сценарии из раздела 22.3 на своём Telegram.

### 22.3. Сценарии приёмки заказчиком
1. Открыть «🪐 Орбита» из меню бота → увидеть «Сегодня».
2. Голосом: «Бензинга 100 минг сўм харажат қилдим» → расход в «Бензин и авто» → изменить на 120 000 голосом → проверить в «Кошельке» на сайте.
3. Голосом: «Мадине до завтра в 15:00 подготовить отчёт, срочно» → исправить исполнителя голосом на Бехзода → «Поставить».
4. Спросить «Bugungi rejalarim nimadan iborat?» → сверить с MA.
5. Открыть Гант → перенести задачу → исполнитель получил уведомление.
6. Поставить вторую задачу на то же время → увидеть ⚠️ и предложение свободного окна.
7. Установить утренний отчёт на ближайшие 5 минут → получить отчёт → сверить с разделом «Отчёты».
8. Дождаться напоминания → «Напомнить через 15 мин» → получить повтор → «Сделал» → проверить на сайте.
9. Нажать «🪄 Спланировать мой день» → проверить, что встречи с фиксированным временем на месте → «Принять план» → увидеть план на Ганте.
10. Открыть «Матрицу» → перетащить задачу из квадранта I во II → проверить в MA.
11. Запустить «🍅 Фокус» на задачу в боте → открыть MA и увидеть тот же таймер → поставить паузу на сайте → бот показывает паузу.
12. Отправить в бот фото чека из Korzinka → проверить сумму, дату и категорию → открыть запись на сайте и увидеть фото чека.
13. Сказать «каждый месяц 5-го аренда 6 миллионов» → получить напоминание (тест с ближайшей датой) → «Оплачено — записать» → расход в «Кошельке».

|---|---|---|---|
| Распознавание узбекской речи и диалектов ниже ожиданий | Средняя | Высокое | Эталонный набор, подсказки STT с именами и категориями, обязательная карточка с правкой; при необходимости — альтернативный сервис STT |

| Задачи без длительности искажают перегрузку | Высокая | Низкое | Длительность по умолчанию, пометка «примерно», подсказка указать длительность |
